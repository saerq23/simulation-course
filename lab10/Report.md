# Лабораторная работа №10: СМО с усложнениями (Методы ООП)

**Цель работы:** Реализовать имитационную модель многоканальной системы массового обслуживания (M/M/c) с двумя дополнительными правилами, используя принципы объектно-ориентированного программирования. Разработать графический интерфейс для ввода параметров и визуализации результатов.

## 1. Реализованные усложнения
В данной работе моделируется система M/M/c/K с нетерпеливыми заявками:

1. **Ограниченная очередь (K > 0).**  
   Если все каналы (приборы) заняты, прибывающие заявки занимают место в очереди. При заполнении очереди до лимита K новые заявки немедленно получают отказ (rejected).  
2. **Нетерпеливость заявок.**  
   Каждая заявка, попадающая в очередь, обладает случайным предельным временем ожидания, распределённым экспоненциально с параметром γ. Если за время ожидания обслуживание не начинается, заявка покидает систему (abandoned). При γ = 0 заявки терпеливы бесконечно долго.

## 2. Архитектура модели (Python, ООП)
Программа написана на языке Python с использованием библиотек Tkinter (GUI) и matplotlib (графики). Основные классы:

- **`Request` (Заявка)**  
  Атрибуты: идентификатор, время прибытия, максимальное время ожидания, момент возможного ухода (`abandon_time`), статус (`NEW`, `IN_QUEUE`, `SERVING`, `SERVED`, `REJECTED`, `ABANDONED`), время начала обслуживания и время завершения.  

- **`Server` (Канал/Прибор обслуживания)**  
  Атрибуты: состояние занятости (`is_busy`), текущая обслуживаемая заявка. Методы `start_service()` и `finish_service()` управляют процессом обслуживания и возвращают время следующего события (ухода из прибора).

- **`EventQueue` (Очередь событий)**  
  Приоритетная очередь на основе кучи (`heapq`). Хранит события трёх типов: `ARRIVAL` (прибытие), `DEPARTURE` (завершение обслуживания), `ABANDON` (уход по нетерпеливости). Извлекает событие с минимальным временем.

- **`Simulation` (Ядро симуляции)**  
  Управляет модельным временем, генерирует поток прибытий, обрабатывает события, ведёт статистику и лог первых 30 событий. Содержит метод `run()`.

- **`App` (Графический интерфейс)**  
  Отвечает за окно параметров, кнопки управления, таблицу событий, сводку результатов и круговую диаграмму исходов.

## 3. Интерфейс и функциональность
Главное окно программы содержит:
- **Панель параметров**: поля для ввода λ, μ, c, K, γ, T. Кнопки «Запустить симуляцию» и «Сброс».
- **Результаты**: сводка из шести основных показателей (всего заявок, обслужено, отказов, ушедших, относительная пропускная способность Q, среднее время в очереди Wq).
- **Таблица событий**: первые 30 записей с временем, типом события, номером заявки и состоянием системы (занятость каналов / длина очереди).
- **Круговая диаграмма**: распределение заявок по исходам – обслужены, отказано, ушли (нетерпение), оставшиеся в системе на момент остановки.
- **Вывод**: текстовое резюме с основными долями.

## 4. Тестирование и результаты
Тестовый запуск выполнен со следующими параметрами:  
λ = 5, μ = 3, c = 2, K = 10, γ = 1, T = 200.

**Полученные показатели (пример):**  
- Всего заявок: 121  
- Обслужено: 78  
- Отказов (нет мест): 9  
- Ушло (не дождались): 22  
- Относительная пропускная способность Q ≈ 0.6446  
- Среднее время в очереди Wq ≈ 1.0524  

**Вывод:** при заданных параметрах примерно 64.5% заявок обслуживается, 7.4% получают отказ из‑за переполнения очереди, а 18.2% покидают систему, не дождавшись обслуживания. Увеличение γ (рост нетерпеливости) или уменьшение K (сокращение очереди) приводит к росту доли потерянных заявок.

Полученные метрики согласуются с теоретическими ожиданиями для многоканальной системы с потерями и уходами.
